## The finding that mattered more than the feature

**`gateway.evaluate()` had no caller outside the test suite.**

The record was wired. `onDecision` was wired. The ordering was proved by six
tests. And nothing in the running server ever *asked for an alert* — so
`recordDecision()` had no production caller, and the write boundary was never
entered.

This is worth stating plainly because it is the same failure as the unreachable
`App.tsx` block from !105, one layer up: **code that is correct, tested, and
never executed.** The test suite exercised the ordering; nothing exercised the
path. Had this shipped on the strength of the green suite, the MR's central claim
would have been true of a code path that no operator could ever reach.

The fix is `LiveGateway.evaluate`, called from the live read path. **And its
limitation is stated rather than left to be discovered:** an alert is raised when
something asks how the stream is doing. A deployment where nobody polls raises no
alerts. That is honest and wrong for a monitoring product at the same time, and the
fix is a scheduler this platform does not have — not a trick hidden in a request
handler. The line is named in `portal-routes.ts` so whoever adds one knows it is
taken.

A timer in the server factory was rejected for a specific reason: it would be a
handle outliving its owner in every test that builds a server without
`startWedgeServer`, and this repository has been hung by exactly that shape.

## Constraint 1 — the token guard actively defends the route

Not "returns 401" — **actively**, meaning the bytes on the socket are asserted:

```
no credential            -> 401, and no content-type was ever written
credential not issued    -> 401, "not recognised"
proven credential        -> 200 text/event-stream
```

Each refusal also asserts that `text/event-stream` **never appeared in the
response**, because a stream that writes `200` and the stream headers and then
refuses is a surface a scanner reads as working and an operator reads as silent.
And a test asserts the stream's refusal is **byte-identical** to the diff route's
refusal — one `prove()`, one answer, and the day they differ is the day a second
authentication path was born.

The tenant is captured at connect from the proven credential and never re-scoped.
There is no `publishAll`; a broadcast helper is one call away from a leak.

## Constraint 2 — slow consumers are disconnected, not buffered

Two conditions, both required: `write()` reports a full buffer **and** the backlog
is past `MAX_CONSUMER_BACKLOG_BYTES` (64 KiB, asserted as a number so raising it is
a reviewed edit). A consumer momentarily behind is kept — disconnecting it would
make the stream useless on a slow network for no reason.

On disconnect it gets a final frame naming the reason and what it actually lost:
*"Reconnect, then read /api/memory/diff. The alert is in the record; only the
notification was lost."* A bare socket close reads as a server fault.

`publish` returns `{ told, dropped }`, because a publish reporting `1` while
nothing reached anybody would let the caller believe a notification landed.

## Live receipt — the real process, the real socket

```
[guard]   no credential          -> 401, content-type: null
[guard]   credential not issued  -> 401
[stream]  proven credential      -> 200 text/event-stream
[stream]  cache-control          -> no-store, no-transform
[ingest]  400 clean events       -> push=200, records=400,  breached=0
[ingest]  900 events, 1 outlier  -> push=200, records=1300, breached=1
[subscriber] received a frame    -> true
[subscriber] severity            -> critical
[subscriber] alert id            -> 1403f4bffeb3f76cfed9fc707e8dd5e1
[record]    alerts in the record -> 1
[record]    first alert id       -> 1403f4bffeb3f76cfed9fc707e8dd5e1
[record]    severity             -> critical
[same id?]  frame == record      -> YES
```

**The same id in both places** is the point. The record and the stream are joined
on one key because both take it from `buildAlertPayload` — so the severity policy
is not re-derived, and a receiver can deduplicate a redelivery against what it
already had.

## Two test defects I found in my own work, which mattered more than the fixes

**The ordering tests compared execution indices.** Not state — indices in a shared
trace, because ADR-005 §5 rule 3 is a claim about *order* and inspecting state
afterwards cannot distinguish the right order from the wrong one. The first version
of that file passed `gateway.push` + `evaluate` in one tick and produced no columns
and no alerts: **five green tests asserting nothing**, because a broker that has
not drained holds no records. It now mirrors the real shape (`broker.start()`,
stream, settle) and asserts the traffic actually arrived before anything else.

**My `FakeResponse.end()` ignored its argument**, so every refusal came back as an
empty string with a correct status line. Five tests failed on a fixture that was
lying rather than on code that was broken. A receipt that cannot fail is not a
receipt — the same lesson as the boot proof that sent its own credential.

And the earlier mend of `memory-routes.ts` used a line range that swallowed the
`openStream` body and the `write` helper. Both restored and typechecked before this
commit; the file compiles and its 31 memory tests pass.

## What this does NOT prove

- **No scheduler.** Stated above: an alert is raised when something polls. That is
  the largest honest limitation in this MR and it is a product decision, not a bug.
- **The browser side.** Nothing in `frontend/` consumes `/api/memory/alerts` yet.
  The stream is server-complete and unproven in a browser.
- **Proxy behaviour.** `no-transform` and the keep-alive comment are correct
  defensive choices, but a middlebox in front was never tested.
- **Multi-consumer load.** One subscriber was proved. The hub has no ceiling on
  subscriber count — deliberate (the gateway is the bound), and stated.
- **Live attribution stays coarse**, as in !105: the wedge's live path carries no
  tenant, so `defaultLatest()` attributes the newest reading to every registered
  agent. Fine for differences 2 and 5, not for attributing a number to an agent.
